Post-quantum authorization · Arc mainnet

USDC that answers to a hash-based key, and nothing else

Olinea holds USDC on Arc and releases it only when an SLH-DSA-SHA2-128s signature — FIPS 205, hash-based, not elliptic-curve — verifies on-chain through Arc's post-quantum precompile. No owner, no admin key, no pause, no upgrade path.

Quantum-resistant by construction

The releasing key is 32 bytes of hash-based public material. A quantum computer that breaks ECDSA still cannot forge a release.

Verified on-chain

The signature is checked inside the transaction by Arc's precompile. No oracle, no committee, no off-chain signer to trust.

No owner, no admin

Nothing can pause the vault, upgrade it or redirect funds. Deposits are open to anyone and grant no rights over the balance.

Replay-proof by construction

Every authorization signs the chain, vault, recipient, amount and nonce together, so it is valid for exactly one release.

How it works

  1. Deploy and deposit. A vault is deployed with a 32-byte hash-based verifying key and holds USDC through Arc's ERC-20 interface. Depositing grants no spending rights.
  2. Authorize off-chain. The key signs one 32-byte digest that binds the chain, vault, recipient, amount and nonce. The signing key never touches the chain and needs no Arc account.
  3. Anyone relays the release. The vault asks the precompile, decodes the returned boolean, and only then transfers the USDC. The relayer pays the gas and gains nothing.

Signing

Keypair generation and signing run in pure JavaScript — no native crypto, no hardware wallet, no extension.

Read the return value, not the call status

This is the one integration rule that matters. A cryptographically invalid signature returns false without reverting, so a contract that checks only whether the call succeeded accepts every forgery: 

// WRONG — true for every forgery
(bool ok, ) = PRECOMPILE.staticcall(data);
require(ok, "verify failed");

// CORRECT — the signature is a value, not an exception
(bool ok, bytes memory ret) = PRECOMPILE.staticcall(data);
require(ok && abi.decode(ret, (bool)), "invalid PQ signature");

Limitations

  • Unaudited. The contracts are new code. The test suite and the mainnet evidence above are what assurance exists today, and they are not a substitute for review. Do not put amounts you cannot lose into an unaudited vault.
  • No recovery. Lose the post-quantum key and the funds are unrecoverable by design — there is no admin escape hatch. That is the property, not an oversight, and it is also why there is nothing for an attacker to phish.
  • Circle's denylist still applies. A forged SLH-DSA signature cannot move funds, but the USDC token itself can still block transfers. Post-quantum authorization is not denylist resistance.
  • Verification is not free. 382,879 gas per release — roughly 1,300× a plain USDC transfer on the same chain, though only about $0.008.
  • Signatures are large. 7,856 bytes of calldata per release, and signing takes seconds rather than milliseconds. That is the price of hash-based signatures.

FAQ

Is Olinea audited?

No. The contracts are unaudited new code. What exists instead is a 17-test Foundry suite, a fixture that proves the naive implementation fails, and a conformance run against the real mainnet precompile. That is meaningful evidence and it is still not a review — treat the vault accordingly.

What happens if I lose the signing key?

The funds are unrecoverable. There is no owner, no recovery address, no pause and no upgrade path — the key fixed at deployment is the only thing that can move USDC out. Back it up the way you would back up a hardware wallet seed, and expect no help if it is gone.

Does this protect me from quantum computers today?

Not today: no quantum computer can break ECDSA yet. The problem Olinea addresses now is that long-lived keys and recorded transactions are already being collected to be broken later. A 32-byte hash-based key cannot be forged even by a fully compromised hot wallet, so it works as a second authorization factor on a treasury well before it is strictly necessary.

Why SLH-DSA rather than a lattice scheme?

SLH-DSA (FIPS 205, the standardized SPHINCS+) rests only on hash functions, so it inherits the most conservative assumptions available. The trade is size and speed: a 32-byte public key, a 7,856-byte signature, and seconds to sign. Arc exposes exactly this scheme as a precompile, which makes it the one that can be verified on-chain today.

What does a release cost?

382,879 gas per release. Arc's base fee is pinned at 20 Gwei and gas is paid in USDC, so a release costs about $0.0077 — roughly 1,300× a plain USDC transfer, and still fractions of a cent.

Can Olinea freeze or seize my USDC?

Olinea cannot: there is no admin, no pause and no upgrade path, and no code path that moves funds except a valid authorization. Circle can still act on the token itself — USDC carries a denylist, and post-quantum authorization does not change that.

Is the precompile interface official, or reverse-engineered?

Both, and that is the point. The interface is documented in Circle's public arc-node source, and every claim on this page was then verified by calling the live precompile on Arc mainnet: a real signature returns true, and a tampered signature, a wrong key and a mismatched message all return false.

Can I use this in my own contract?

Yes. The vault is MIT-licensed and the pieces are separable: the vault, the interfaces, and an authorize command that prints a signature plus a ready-to-run submission. The one rule to carry across is to decode the boolean the precompile returns — an invalid signature succeeds as a call and returns false. The docs cover the digest, the exact ABI and the failure modes.
